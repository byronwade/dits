# CLI Reference

**Maturity:** Current

This page is the v0.1.5 command map for the canonical Rust CLI. Command existence
does not imply that a related network, encryption, or media workflow is production
ready. Exact arguments and flags are generated by the executable and may change
during the alpha.

## Runtime authority

Use runtime help for the exact command surface installed on your machine:

```bash
dits --help
dits <command> --help
```

The only top-level flags are `-h`/`--help` and `-V`/`--version`. Options such as
verbosity, color, repository selection, or JSON output are command-specific when
they exist; they are not global flags.

Output wording is not a stable machine-readable API. Scripts should check exit
status and avoid parsing decorative console output unless a command explicitly
documents a structured format.

## Safe local start

Set an explicit commit identity, initialize a repository, stage paths, and commit:

```bash
export DITS_AUTHOR_NAME="Your Name"
export DITS_AUTHOR_EMAIL="you@example.com"

mkdir project && cd project
dits init
dits add README.md
dits status
dits commit -m "Initial snapshot"
dits log
```

`DITS_AUTHOR_NAME` and `DITS_AUTHOR_EMAIL` take precedence over Git author
environment variables and local OS defaults. Configuration keys do not define
commit identity.

Keep independent backups while evaluating the alpha. Checkout, reset, restore,
clean, merge, rebase, cherry-pick, and lifecycle commands can change working-tree
or repository state; inspect each command's help before using it on important data.

## Current local history commands

| Area | Commands | Boundary |
| --- | --- | --- |
| Repository and staging | `init`, `add`, `status`, `commit` | Local repository state and snapshots. |
| History inspection | `log`, `show`, `diff`, `blame` | Output is human-oriented unless the command says otherwise. |
| Refs and navigation | `branch`, `switch`, `checkout`, `tag`, `reflog` | Local refs only; no remote tracking workflow. Reflog records commit and checkout; other ref changes may omit entries. |
| History changes | `merge`, `rebase`, `cherry-pick`, `reset`, `restore`, `bisect`, `stash` | Alpha conflict and recovery behavior; back up first. `restore --ours/--theirs` fails closed. |
| Configuration | `config` | Selects one local or global file; see the configuration reference. |

Use `dits <command> --help` for required operands and modes. In particular,
`checkout` uses `--mode full|proxy`; branch creation is a separate `branch`
operation rather than a documented `checkout -b` shortcut.

## Current local storage and utility commands

| Area | Commands | Boundary |
| --- | --- | --- |
| Integrity and storage reports | `inspect-file`, `repo-stats`, `fsck`, `gc` | `gc` requires `--dry-run` and never deletes objects or locks. |
| Metadata | `meta-scan`, `meta-show`, `meta-list` | Local extracted metadata; no hosted catalog. |
| Dependencies | `dep-check`, `dep-graph`, `dep-list` | Local project-file analysis bounded by supported parsers. |
| Lifecycle | `freeze-init`, `freeze-status`, `freeze`, `thaw`, `freeze-policy` | Local storage tiers; verify source availability before transitions. |
| Audit | `audit`, `audit-stats`, `audit-export` | Local audit data, not a hosted compliance service. |
| Local object copy | `fetch-objects` | Additive object copy from another local repository; does not update refs or the working tree. Not a substitute for `fetch`/`pull`. |
| Local locks | `lock`, `unlock`, `locks` | Advisory local locks; no remote lease coordinator. |
| Working-tree tools | `clean`, `grep`, `worktree`, `sparse-checkout`, `hooks` | `clean` can delete untracked data; preview with `--dry-run`. |
| Packaging and history summaries | `archive`, `describe`, `shortlog` | Local repository content and refs. |
| Maintenance and shell support | `maintenance`, `completions` | Destructive GC stays disabled. `maintenance run pack`, `incremental-repack`, and `prefetch` fail closed without packing or fetching. |
| Telemetry | `telemetry` | Explicit `enable`, `disable`, or `status`; disabled by default. |

Malformed repository configuration prevents repository commands from opening it
and is left untouched. Malformed global configuration disables telemetry for
unrelated commands, and telemetry/config mutations refuse to overwrite malformed
TOML. See [Configuration](./config-reference.md) for the complete schema and
file-selection rules.

## Experimental and feature-gated commands

These commands are real local experiments, not universal media or collaboration
contracts:

| Area | Commands | Boundary |
| --- | --- | --- |
| MP4 inspection and reconstruction | `inspect`, `roundtrip`, `segment`, `assemble` | Tested fixture/container subset; preserve the original. |
| Virtual filesystem and cache | `mount`, `unmount`, `cache-stats` | Local only; mount support requires the optional `fuser` build feature. |
| Frame-addressable video | `facr-demo`, `facr-add`, `facr-checkout`, `facr-trim`, `facr-import-edl`, `facr-import-otio` | Experimental; FFmpeg is required where runtime help says so. |
| Streaming demonstration | `stream-demo` | In-process experiment, not a repository sync protocol or hosted service. Use `--report-only` to print byte/reuse results without starting the HTTP player. |
| Photo rendition experiment | `photo-add`, `photo-edit`, `photo-render` | Non-destructive edit demonstration; not a DAM or RAW pipeline. |
| Timeline experiment | `video-init`, `video-add-clip`, `video-show`, `video-list` | Local metadata workflow with bounded parser support. |
| Proxy experiment | `proxy-generate`, `proxy-status`, `proxy-list`, `proxy-delete` | Derived local media; originals remain authoritative. |

FACR identities, edit manifests, proxies, and container structure do not create a
universal decoded-frame identity and do not guarantee reuse after re-encoding or
recompression.

## Limited, disabled, and fail-closed commands

Network transfer status: **fails closed, no data transfer**. The P2P command surface
is retained as disabled scaffolding and is not an active sharing workflow.

| Commands | Current behavior |
| --- | --- |
| `clone` | A validated local filesystem source works and preserves its current HEAD/config unless `--branch` selects another source branch. Network clone fails; no repository network protocol is shipped. A failed checkout returns nonzero and may leave a clearly reported incomplete destination for inspection. |
| `remote` | Adds, removes, renames, and inspects local remote metadata only. It does not transfer data. |
| `push`, `pull`, `fetch`, `sync` | Return a nonzero error without changing objects, refs, or the working tree. For additive local object copy use `fetch-objects`; for a full local copy use `clone`. |
| `p2p` | Parsed operations fail nonzero before repository, target, cache, socket, or mount mutation. |
| `encrypt-init`, `login`, `change-password` | Disabled experiment; each fails without changing the keystore. |
| `encrypt-status`, `logout` | Inspect or clear legacy experimental state; they do not enable supported encryption. |
| `serve` | Real unauthenticated object server (loopback by default). It is not sync and must not be exposed to the public Internet. |

`serve` defaults to `127.0.0.1`, disables CORS, and validates repo/object paths.
`--bind` to a non-loopback address still has no authentication—use only on a
trusted or isolated network behind a firewall.

## Exit and safety model

- Successful operations exit zero; validation, disabled capability, and integrity
  failures exit nonzero.
- Transfer and encryption commands above fail closed rather than printing a
  success placeholder.
- `fsck` is read-only and verifies the current bounded integrity contract.
- `gc` is analysis-only even when reserved pruning flags are present.
- No command provides hosted authentication, authorization, remote locks, or a
  stable public repository protocol.
